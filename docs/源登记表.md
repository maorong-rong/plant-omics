**SCOD 要点**（2026-10-29 实测，共 13 次请求）：

- **定级 T2**：有参数化 URL、四个端点实测 200 JSON，但拿不出 API 文档地址，够不上 T1。
- **区间语义：整条基因完全落在区间内才返回**。决定性反例 `posStart=130574&posEnd=133000` → 0 条（目标基因 130574–133277 终点越界）；`131000-136000` 与基因明显重叠却 0 条，因此**不是"按起点"也不是"任意重叠"**。
- **`length` 必须本地限 ≤ 50**：`length=1000` 实测 2.0 MB / 45.6 秒，超过 20 秒上游超时；默认 10 条、`length=50` 为 112 KB / 2.6 秒。
- **两套信封并存**：`genome/list` 是裸数组，`gene_list` 是 DataTables `{draw, recordsTotal, recordsFiltered, data}`；`recordsTotal` ≠ `data.length`（分页时 11 vs 2）。
- **`posStart`/`posEnd` 是字符串**（`"130574"`），不是数字。
- **染色体命名是 `Chr1A`（大写 C）**，这是本仓遇到的第三套命名。
- **0 条不等于"该位置没有基因"**：窄区间包不住基因终点时会静默返回 0，属完全包含语义的正确结果，但对用户是陷阱，正文必须提示。
**WheatOmics 要点**（写清楚，免得下次重新查）：

**2026-10-29 新增三项能力**（工具数 6→9）：

- `wheatomics_cross_species_homologs`：按基因 ID 查 wheat/rice/arabidopsis 同源；上游返回**没有直系/旁系字段**，故命名用 `homologs` 而非 `orthologs`，正文写明"不区分"；`max_targets` 是**每物种**上限（实测 Rice 3 + Arabidopsis 3）。
- `wheatomics_variant_datasets`：变异数据集目录；`genome_concordant` 除 WEC(false)/whealbi(true) 外**其余 27 个未记录，显示"未知"**，不替上游推断。
- `wheatomics_variant_query`：按区间查变异；`total=0` 是成功结果，正文强制带"0 条不等于该区间没有变异，请先确认 `genome_concordant`"。`variant_id` 查询**不暴露**：实测 19 s 全文件扫描，逼近 20 s 超时，网络抖动即失败。

> ⚠️ **证据等级**：上述三项的 5 个 fixture 均为**结构回放件（`simulated: true`）**，不是真实快照——落地时上游整体 503，无法采集。它们能证明解析自洽，**不能证明上游契约已被快照钉住**；恢复后必须替换为真实抓取。坐标基数（1-based）**未由本仓证实**，正文已写明。

- 信封统一 `{success, message, timestamp, data}`；`success=false` 时 `data` 不可用。
- **版本口径：本仓不判定，只转述上游。** 上游 `genome` 字段返回 `Chinese_Spring1.0`；
  JBrowse 轨道写 `IWGSCv1.1_HC_LC`；基因 ID 有 `01G/02G/03G` 三种前缀，而各端点对
  "v1/v2/v3"的叫法并不一致。**组装版本、注释版本、站点内部映射表是三件事，不能按 ID 外观互相推断。**
  > ⚠️ 2026-10-28 更正：本表此前一处写"表达量基于 IWGSC v2.1（02G）"、另一处写"统一转 IWGSC v1.1（02G）"，
  > 属**转述不一致**（审查 R06）。现在统一改成本段口径，并在 `manifest.versionNote` 里原样透出到每条工具输出。
- 表达值单位随项目而定且上游未逐点标注，**跨项目不可直接比较大小**。
- 平台**自带 MCP server**（`GET /api/mcp/sse`），但**实测不可用**（2026-10-28）：端点真实存在
  （200 `text/event-stream`，回 `endpoint: /api/mcp/messages?session_id=…`），
  但 20 次新建会话只有 **1 次**被接受，其余全部 `404 Could not find session`；
  拿不到会话就发不出 `tools/list`，因此**其工具清单至今未知**。
  该端点是 MCP Python SDK 的**旧 SSE 传输**——`@deepseek-ai/dsh-mcp-client` 只支持 stdio 与
  streamable-http，**接不了**。⇒ 结论：本仓继续走 REST 适配器；**不要把它的 MCP 当依赖**。
- `GET /api/expression/projects` 单次返回约 **600 KB**，任何场景都不许整表透传给模型。

**IC4R 要点**（2026-10-28 实测，六类意图）：

- 按 ID 五端点均 200 JSON：`gene` 384 B、`annotation` 2,565 B（**数组**）、`circRNA` 490 B、`lncRNA` 1,891 B、`idConversion` 99 B。
- **查无 = HTTP 200 + 0 字节正文**（`annotation` 为 `[]` 2 B），没有 404、没有错误 JSON。本仓把 0 字节报成“无法确认是否存在”，`[]` 只表示本次未返回注释，都不判“记录不存在”。
- **列表端点不在 `apiBase` 下**：`GET https://ngdc.cncb.ac.cn/ic4r/genes/view?chromosome=1&draw=1&start=0&length=2` → 200 / 847 B，`recordsTotal=6534`，`data[].locus` 如 `IC4R-OSJ01G000100`。参数必须用 DataTables 的 `draw/start/length`（`limit/offset` 实测 400）。
- 染色体取值来自 `/ic4r/genes/browse` 内联下拉枚举 **1–12 / Sy / Un**（`Sy` 实测 200、`recordsTotal=140`）。
- **`chromosome=99` 实测返回 200 / 70 B / `recordsTotal=0`**——上游对枚举外取值**不报错、只回零记录**。因此本仓拒绝 99 是**产品层白名单约束，不是上游限制**。
- 限制：**仅粳稻**（`Oryza sativa Japonica Group`，indica 未核验）；**文档为 2018 版**（引用写“IC4R 2.0（文档声明，2018-05）”，不当数据版本）；**不能按基因名、性状或区间检索**，只能按染色体分页浏览；`length` 的上游上限未测（本仓自限 50）；circRNA/lncRNA 列表端点未验证。
- `accession` 与 `locus` 是不同 ID 空间（`…Circ…`／`…Lnc…` 不与基因 locus 通用）；ID 映射只承诺已测方向（IC4R `locus` → MSU/RAP-DB）。

## 六、Gramene 接入边界

- 四个工具对应四个意图：全文检索（`q`）、基因、差异表达、分类单元。`/search` 用 `q`，其余只收 `idList`；`q` 传给非 search 端点只会得到空数组。
- **`idList` 是数组参数**：数值型单值 `idList=4530` 实测返回 400（`Expected type array but found type integer`）；本仓对单值也重复发送一次并按 `_id` 去重，输出注明该规避写法。
- **身份对账**：返回 `_id` 不在请求集合内即抛"身份不符"；请求了未返回的 ID 逐个列出，不写成"不存在"。
- **`/search` 的 content-type 是 `text/plain`**，正文是 JSON；本仓按正文解析，不按 content-type 分流。
- 查无 = HTTP 200 + 空数组（`/search` 为 `numFound=0`）；`start` 越过末页单独报"已越过末页"，不与无匹配混为一谈。
- 覆盖只写实测：`Oryza sativa`（4530）、`Oryza sativa Indica Group`（39946001），不外推禾本科。版本口径只写 v69，与 Ensembl 版本对应关系未核验。
- 裁剪：单基因原 8.5 KB 含 `xrefs`，工具不返回；表达每实验最多 3 个、每实验 2 个比较；`facet_counts` 不读、`ancestors` 只给长度。
