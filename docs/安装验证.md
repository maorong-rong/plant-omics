## 新用户应检查什么

1. 保存源码提交SHA或可信tgz及其完整SHA256。main会变化，本项目当前不承诺有版本tag或Release下载附件。
2. 源码用户执行 `npm ci`、`npm run check`。MCP只需Node和支持stdio的客户端，不需DSH；DSH用户须先将构建结果打为tgz，源码ZIP不能替代tgz。
3. MCP配置使用Node与入口的绝对路径，重启客户端MCP进程。DSH使用插件管理页，按提示重启后新开会话，不手改profile依赖。
4. 查询已知示例：GWH组装 `GWHAAAA00000000`，或ICG物种 `ICG00115`。检查实际工具名、完整请求、HTTP状态与查询时刻；网页面板显示工具数不等于查询成功。
5. 检查无覆盖问题：不能因工具无法覆盖而断言生物学不存在，也不调用错误物种的库凑答案。

2026-10-28，针对此前 `npm audit` 报告的3项开发依赖问题（`vitest`、`tinypool`、`@vitest/mocker`，含critical），已把开发依赖精确锁定为 `vitest 4.1.12` 与 `vite 7.3.7`（跨Vitest主版本，理由见CHANGELOG）。

- 隔离复验：干净 `npm ci` 后完整 `npm run check` 通过，13文件295例、4源15工具，测试配置与断言未改。
- 审计命令与退出码（在隔离副本逐条执行）：`npm ci; npm run check; npm audit; npm audit --omit=dev`，均退出0，两次审计当次均0项。本次验证日志未随仓库发布，如需复核请自行重跑上述命令。
- 生产依赖（`@modelcontextprotocol/sdk`等）版本未变；`tinypool`移除、无Vite8/Rolldown。

这仍是**当次审计结果**，不是安全保证：新公告、新版本或不同registry镜像都可能改变结论。不要对不可信网络开放开发/测试服务；上线前请自行重跑上述命令。运行时依赖当次为0项，也不能推广成“所有依赖长期无漏洞”。

另需披露：本次`npm ci`后lock根条目中陈旧的`peerDependencies`（`@deepseek-ai/cordis`）被npm清理。候选`package.json`从未声明该字段，属版本同步之外的lock结构变化，不影响宿主加载。

## 不作的承诺

- Linux/macOS、其他Node或DSH版本尚未实测；命令兼容写法不等于已验证。
- 不承诺外网一定可访问各上游，也不把DNS/代理/5xx归因于单一原因。
- 本轮不分发安装辅助脚本；只验证手动打包与桌面插件管理器路径，不承诺自动归档或自动安装。
- 本地重新构建的同版本包可能因构建时刻、文档等不同而哈希不同；不要用维护者旧候选哈希认证新包。
- 源码仓库可用不等于项目已在npm发布，也不等于tgz已有公开下载入口。
