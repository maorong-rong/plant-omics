# 安装路径与验证边界（0.1.0）

安装命令见[README](../README.md#安装)。本页区分“能安装”“工具能调用”与“模型会正确使用”，不把其中一项代替另一项。

## 已有证据

2026-10-28，Windows、Node 24.14.0、npm 11.9.0（当时包版本 0.5.0，属历史快照，不代表当前 0.1.0 包的验收状态）：

- 源码类型检查、离线fixture及协议测试、构建和预算检查通过；默认4源15工具。
- 维护者候选tgz隔离安装通过；包内MCP stdio同会话列工具并调用各源代表工具，保留完整出处。
- 四源选定probe端点通过；不代表全部端点长期可用。
- 包内DSH `apply(fakeCtx)`、fixture回放与render通过。这不是实际宿主问答验收。
- 用户已报告在本机安装0.5.0；“模型选择工具→查询→带出处回答”的现场验收仍单列。

## 新用户应检查什么

1. 保存源码提交SHA或可信tgz及其完整SHA256。main会变化，本项目当前不承诺有版本tag或Release下载附件。
2. 源码用户执行 `npm ci`、`npm run check`。MCP只需Node和支持stdio的客户端，不需DSH；DSH用户须先将构建结果打为tgz，源码ZIP不能替代tgz。
3. MCP配置使用Node与入口的绝对路径，重启客户端MCP进程。DSH使用插件管理页，按提示重启后新开会话，不手改profile依赖。
4. 查询已知示例：GWH组装 `GWHAAAA00000000`，或ICG物种 `ICG00115`。检查实际工具名、完整请求、HTTP状态与查询时刻；网页面板显示工具数不等于查询成功。
5. 检查无覆盖问题：不能因工具无法覆盖而断言生物学不存在，也不调用错误物种的库凑答案。

## 开发依赖安全状态

2026-10-28，`npm audit` 对当前锁文件报告3项开发依赖问题（`vitest`、`tinypool`、`@vitest/mocker`，含critical）；建议修复涉及Vitest跨主版本，尚未升级。不要把源码安装描述为“无已知漏洞”，也不要对不可信网络开放开发/测试服务。隔离tgz安装及 `npm audit --omit=dev` 当次报告0项，这只说明该次运行时依赖审计结果，不是安全保证。

## 不作的承诺

- Linux/macOS、其他Node或DSH版本尚未实测；命令兼容写法不等于已验证。
- 不承诺外网一定可访问各上游，也不把DNS/代理/5xx归因于单一原因。
- 辅助安装脚本只做预检与本地归档，不替代桌面管理器，不构成来源认证。
- 本地重新构建的同版本包可能因构建时刻、文档等不同而哈希不同；不要用维护者旧候选哈希认证新包。
- 源码仓库可用不等于项目已在npm发布，也不等于tgz已有公开下载入口。

升级与回滚见[README](../README.md#升级验证与回滚)。保留旧包与已验证提交；不要通过删除profile数据实现回滚。
