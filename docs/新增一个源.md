# 新增一个源 · 照单执行

> 目标：**别人（或三个月后的你）照这份清单能加一个源，不用读源码。**
> 源状态见 [源登记表](源登记表.md)，公共契约与输出设计见 [架构](架构.md)。

---

## 第 0 步 · 实测定级（不许跳）

| # | 动作 | 判据 |
|---|---|---|
| 1 | 打开首页 + 文档页，找接口说明 | 有 OpenAPI / REST 文档 / 官方 curl 示例 → 候选 T1 |
| 2 | 用 `curl -sS -o NUL -w "%{http_code} %{content_type}"` 打**至少两个**候选端点 | `application/json` 才算数；`text/html` 要警惕 SPA 兜底 |
| 3 | 若是 SPA：抓 `js/app.*.js` 等 bundle，搜 `/api/`、`baseURL` | 找到 base 才继续；找不到**按 T3 记，不许猜路径** |
| 4 | 把现象（**含日期**）写进 `docs/源登记表.md` | 写清"试过什么、返回什么" |

**任一步没过，就停在 `docs/源登记表.md`，不要进 `src/sources/`。**

---

## 第 1 步 · 建目录

```
src/sources/<id>/
├── manifest.ts
├── tools.ts
└── fixtures/
    ├── README.md
    └── <端点名>.json
```

`<id>` 用小写字母+数字（如 `wheatomics`、`ngdcgsa`），它同时是**工具名前缀**。

---

## 第 2 步 · `manifest.ts`

```ts
import type { SourceManifest } from '../../core/types.js';

export const manifest: SourceManifest = {
  id: '<id>',
  displayName: '<中文名>（<机构>）',
  homepage: 'https://…',
  apiBase: 'https://…/api',        // 不许带尾斜杠
  tier: 'T1',                       // T1 必须给 docs；T3 不许有工具
  docs: 'https://…/api/docs',
  auth: 'none',
  species: ['Triticum aestivum'],   // 拉丁名
  network: 'direct',                // 本机实测：direct / proxy-required / unknown
  probe: { path: '/ping', expectStatus: 200 },
  lastProbe: { date: 'YYYY-MM-DD', ok: true, status: 200 },
  caveats: ['一句话一条，会被透出到工具描述里'],
};
```

`caveats` 不是装饰：它会在你三个月后忘了这个源的坑时提醒你。

## 第 3 步 · `tools.ts`

**一个源给 4–8 个"意图级"工具，不是端点 1:1 翻译。**

命名：`<id>_<动词短语>`，如 `wheatomics_search_known_genes`。

```ts
const myTool: ToolDefinition = {
  name: '<id>_<verb>',
  description: '什么时候该用它 + 这个源覆盖什么、不覆盖什么（盲区要写）',
  parameters: {
    type: 'object',
    properties: { q: { type: 'string', description: '…' } },
    required: ['q'],
    additionalProperties: false,
  },
  async run(args, ctx) {
    const url = endpoint('/search', { q: requireString(args, 'q') });   // 见下
    const res = await ctx.http(url, { signal: ctx.signal });
    const data = unwrap<MyShape>(res.data, url);                        // 见下
    return result(renderTable([...], ...), res, data);                  // 见下
  },
};
```

三个小工具**照结构抄、不要照语义抄**（审查 R07）：`src/sources/wheatomics/tools.ts` 顶部的
`endpoint()` / `unwrap()` / `result()` 只是**这一个源**的写法。

- `endpoint()` 负责拼 URL 与查询参数（自动 `encodeURIComponent`）；
- `unwrap()` 拆的是 WheatOmics 的 `{success,message,data}` 信封 —— **换一个源必须换掉它**。
  例如 NDGC 门户是 `{code:"200", message, data}`（注意 `code` 是**字符串**），Strawberry 又有自己的信封。
  **业务信封一律按该源实测到的来写**，不许套模板。
- `result()` 三个源可以共用同一个（它只依赖 `HttpResult` 与 manifest）。

**输出三件事必须做到**：

1. 有界：**≤ 4 KB（UTF-8 字节）**，大响应先聚合；截断由 `result()` 统一执行，出处不许被截掉；
2. 带出处：`源 / 完整请求（含参数）/ HTTP 状态 / 耗时 / 查询时刻` + 版本口径；
3. 不透传原始 JSON。

**结构校验不要用 `?? []`**（审查 R03）：关键容器字段用 `requireArrayField(data, 'records', url, '…')`，
字段缺失/类型不对一律抛，只有**真的返回空数组**才当作"0 条结果"。

## 第 4 步 · 抓 fixture

```bash
curl -sS 'https://…/api/xxx?param=value' -o src/sources/<id>/fixtures/xxx.json
```

- **只保留断言用得到的量**（大响应用 node 脚本裁到前 N 条）；
- `fixtures/README.md` 写明：抓取日期、真实 URL、裁掉了什么；
- fixture 里**不许有** token / cookie / 个人信息。

---

## 第 5 步 · 离线测试

```
test/<id>.test.ts
```

照 `test/wheatomics.test.ts` 的 `contextFor()` 抄：注入一个回放 fixture 的 `Fetcher`，不联网。

至少覆盖：

- [ ] 工具名/参数 schema 合规（前缀、`type: object`）
- [ ] URL 拼装正确（路径 + 关键查询参数）
- [ ] 正常响应能解析出关键字段
- [ ] **输出有界**（`expect(Buffer.byteLength(text, 'utf8')).toBeLessThanOrEqual(4096)`）
- [ ] 上游 `success=false` 时**抛错**而不是返回空表
- [ ] 非法参数被拒且**不发请求**（`expect(urls).toHaveLength(0)`）

---

## 第 6 步 · 注册

`src/sources/index.ts` 的 `bundles` 数组加一行：

```ts
{ manifest: myManifest, tools: myTools },
```

注册表会跑硬校验：前缀不对、T3 挂工具、T1 缺 docs —— 都会在启动时直接崩。

---

## 第 7 步 · 同步文档（漏了等于没做完）

- [ ] `docs/源登记表.md`：从"未接入"挪到"已接入"，填等级/实测日期
- [ ] `README.md` 的「现在支持什么」与「工具清单」两张表
- [ ] `CHANGELOG.md` 加一条

---

## 第 8 步 · 验收

```bash
npm run check                        # typecheck + 全离线测试 + build + 预算自检
npm run probe -- --source <id>       # 联网判活（含业务信封判定）
npm run stats                        # 看工具额度还剩多少
```

三条全绿才算通。**`probe` 挂了先判断是"上游挂了"还是"我们拼错了 URL"**——
看 `docs/源登记表.md` §四 的记录格式，把结论补进去。

⚠️ **加完源必看 `npm run stats`**：工具额度是紧约束，`check` 里已经在盯着，但你要知道还剩多少——
按当前工程预算，工具逼近 40 就该停下来做检索层，而不是继续加库。
