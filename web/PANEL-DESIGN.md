# 侧边栏面板设计稿（v1 + v2 蓝图）

> 状态：**设计稿**。实现归 `代码改动者`（`src/client/`、`scripts/build-client.mjs`），本稿只定信息层级、三态、与 `web/` 的复用边界。
> 配套线框：`web/panel-sketch.html`（可点开，含状态切换；数据读 `web/data/catalog.js`）。

---

## 1. 面板是什么、不是什么

DSH 侧边栏里的一块常驻面板，回答一件事：**这个插件现在能查什么、怎么查**。

- **是**：源的清单（置顶 + 图标 + 工具数 + 盲区）、工具详情（何时用、必填参数）、跳去试调页的入口。
- **不是**：不是调用界面（试调在 `web/`，面板里放不下参数表单与结果）、不是探活仪表盘（不显示上游此刻是否可达）、不是配置页（token 由插件配置提供，面板不收 token）。

**首版（v1）**：构建期快照——数据由 `scripts/build-client.mjs` 从注册表注入，面板只渲染静态事实。
**第二版（v2）**：加宿主路由取实时数据（`tools/list`、`/healthz`），并在用户按子集加载时核对服务端是否真的按子集返回。

## 2. 信息层级

一屏只做一件事，从上到下三级：

```
┌ 面板头 ────────────────────────────────┐
│ ● 已连接 · 8 源 / 37 工具   [快照 10-31]│  ← 状态 + 规模（口径标在 title）
└────────────────────────────────────────┘
┌ ① 源列表（可滚动，默认焦点）─────────────┐
│ [🍓] Strawberry Data Hub   5 工具  T1  │  ← 草莓置顶
│ [🌾] WheatOmics            11 工具 T1  │
│ [🗄] GWH                    2 工具  T1  │
│ …                                       │
└────────────────────────────────────────┘
┌ ② 工具详情（点工具后展开，覆盖列表）──────┐
│ ← 返回                                   │
│ wheatomics_search_known_genes           │
│ 何时用：……（截断到 320 字符）           │
│ 必填：searchid                          │
│ [在试调页打开 →]                        │
└────────────────────────────────────────┘
```

规则：
- **源列表优先**：面板打开即列表，不先给详情；详情是「点进去」的第二级。
- **置顶**：与落地页同一份顺序（`strawberry` 在最上，其余保持注册顺序）。顺序必须由数据层给，面板不重排——两处各排一次迟早不一致。
- **一源一卡**：图标（复用 `source-icons.js`）+ 名称 + 工具数 + 等级徽章。物种与盲区不展开在卡上，进详情。
- **工具详情**只显示三样：工具名、何时用（一句）、必填参数名。参数 schema 不在这里展开（表单在 `web/`）。

## 3. 三态（空态 / 载入态 / 错误态）

| 态 | 触发 | 面板显示 | 不允许 |
|---|---|---|---|
| **载入态** | 面板刚打开、快照尚未注入 | 骨架屏（3 行灰块）+ 状态行「正在读取构建期清单…」 | 不显示任何数字（0 源也不算） |
| **空态 A**：无快照 | bundle 里根本没有 client catalog | 「清单未注入」+ 一行说明（构建脚本）；列表区完全空，不给假数据 | 不展示「0 个源」这种像结论的数字 |
| **空态 B**：有快照、无服务（v2） | `/healthz` 不通 | 「服务未连接」灰条 + 仍显示构建期清单，但**每张卡标灰并禁止跳转试调** | 不显示「可调用」的工具数 |
| **错误 401**（v2） | token 不被接受 | 顶部红条「token 被拒」；不显示 token 片段；列表仍可看 | 不重试轰炸、不回显 token |
| **错误 403**（v2） | 域名未白名单 | 顶部红条「服务端拒绝来源」+ 该改的配置名 | 不让用户改代码 |
| **错误：服务端未按子集返回**（v2） | 发了 `x-plantomics-sources` 但 `tools/list` 返回的不符 | 顶部**黄条**：「服务端未按子集返回（返回 N 个，非所选的 M 个）」+ 列表按**实际返回**渲染 | **绝不显示「已按你的选择过滤」** |

载入态超过 8 秒：状态行改「仍在读取…」，不报错（构建期数据本来应该秒到，慢说明注入有问题，但先不吓人）。

## 4. 与 `web/` 的复用边界

| 东西 | 复用 | 原因 |
|---|---|---|
| `web/data/catalog.js` 的形状（sources/tools/budget） | ✅ 概念复用，**不共用文件** | 面板用 `src/client/catalog.ts` 的 `ClientCatalog`，字段更少（无 summary 长文、`required` 是名字数组）；两个消费者共享「口径」而不是「实现」 |
| `source-icons.js` 图标与主色 | ✅ 直接复用 | 同一个源在两处必须是同一个符号，否则用户以为换了东西 |
| 措辞规则（token 生命周期、快照口径、「选源不是权限隔离」） | ✅ 复用结论 | `web/scripts/check-wording.mjs` 只扫 `web/`；面板的文案由实现方按同一口径写，本稿把定稿句给出 |
| 试调页（参数表单、结果区、出处高亮） | ❌ 不复用 | 面板宽度 ~320–360px，表单与结果放不下；强行塞进去会做成「什么都做不好」 |
| token 输入框 | ❌ 不复用 | 面板的 token 来自插件配置（`PLANTOMICS_HUB_TOKEN`），用户不该在面板里粘贴 |
| 路由与 hash 导航 | ❌ 不复用 | 宿主有自己的一层路由；面板用「列表 ↔ 详情」两态切换 |

**共享的必须是口径，不是代码**：两处都从注册表取数、都用同一份置顶顺序、都用同一套图标，但各自渲染自己的界面。

## 5. 子集核对在面板里怎么落（v2）

`web/` 的做法（发头 → 回读 `tools/list` → 比对 → 不一致就明说）在面板里**同样适用**，具体化成三步：

1. 面板按当前启用源（来自插件配置 `PLANTOMICS_SOURCES` 或用户在面板上的勾选，v2 才有勾选）带 `x-plantomics-sources` 请求 `tools/list`；
2. 收到结果后，与「按所选源应有的工具集合」比对（含 2 个 `hub_*`）；
3. 三种结果：
   - 一致 → 状态行「已按 N 个源加载（M 个工具）」；
   - 返回全集但只选了子集 → 黄条「**服务端未按子集返回**（可能是旧版本）」，并显示实际工具数；
   - 400 → 显示服务端 `detail`（未知源 id 等），不吞掉。

**验收点**：把面板指向一个不认这个头的旧服务端，必须看到黄条；看到绿勾就算失败。

## 6. 顺序、置顶与「一处真相」

现状问题（实现方需要接线）：`src/client/catalog.ts` 的 `buildCatalog()` 现在按注册顺序输出，注释也写着「面板不重排」；而落地页已按本涛要求把草莓置顶。
本稿要求：**面板与落地页用同一份置顶规则**（`strawberry` 在最前，其余注册顺序），且这个规则只能有一处定义（落地页在 `site/scripts/build-data.mjs` 的 `PINNED_SOURCE_IDS`）。建议实现方把该常量提到共享处，或至少在 `buildCatalog` 里用同名常量并在测试里断言「两个产物的顺序一致」。

## 7. 文案定稿（直接抄，别改写）

- 状态行（v1）：「构建期清单 · 8 源 / 37 工具」，title：「数字来自构建期注册表，不代表上游此刻可用」
- 空态 A：「清单未注入」/「构建脚本没有产出 client catalog，面板暂无可显示的内容」
- 空态 B：「服务未连接」/「仍显示构建期清单；连接服务后才能跳转试调」
- 401：「token 被拒」/「插件配置里的 PLANTOMICS_HUB_TOKEN 与服务端不一致」
- 403：「服务端拒绝来源」/「把 DSH 所在域名加入 PLANTOMICS_HUB_ALLOWED_HOSTS（只写主机名，不带协议与端口）。服务端不下发 CORS 头，跨源配置也治不通。」
  （两句都在界面里：只写主机名是 `src/service/config.ts` 自己要求的写法；「不下发 CORS 头」是全库无 `Access-Control` 响应头的事实，两条都直接影响用户怎么修。）
  （界面上**不要**写「不回显 token 片段」这类自证句——那是给评审看的说明，用户不需要被告知系统没泄露什么。）
- 子集不符：「服务端未按子集返回（返回 N 个，非所选的 M 个）」/「可能是旧版本服务端不认 x-plantomics-sources；面板按实际返回显示，不冒充已过滤」
- token 生命周期（若面板里出现任何提示）：「同一标签页内刷新仍保留；关闭标签页通常会清除，但浏览器恢复会话时可能保留。要立刻结束，请点「清除 token」。」

## 8. 不做的事

- 不在面板里跑调用（结果需要大面积，且出处尾注要完整可读）。
- 不显示上游探活/耗时（那是 `probe` 与 `/healthz` 的事，面板显示会误导成实时监控）。
- 不在面板里存 token、不写 localStorage、不把 token 放进 URL。
- 不为了塞功能牺牲首要任务：面板的第一职业是「告诉你能查什么」。

## 9. 给实现方的验收清单

- [ ] 面板打开到可见 < 300 ms（纯静态渲染，无网络等待）
- [ ] 列表顺序与落地页逐个一致（草莓在最上）
- [ ] 三种态都可复现：无 snapshot / 有 snapshot 无服务（v2）/ 401（v2）
- [ ] 子集不符时出黄条且**不出现**「已按你的选择过滤」字样
- [ ] 面板内任何位置都不出现 token 片段；`grep -r "Bearer " src/client/` 只应命中占位说明
- [ ] 375px 窄面板下无横向溢出；长工具名省略号而非换行撑破

## 10. 已实现 / 未实现（2026-10-31 接线后，代码改动者填）

**已实现（v1）**

- §2 信息层级：源列表优先、置顶在前（顺序来自 `src/core/pinned-sources.json`，面板不重排），一行一个源：图标 + 名称 + 工具数 + 盲区条数 + 等级徽章 + 置顶徽章。
- 点源进第二级：← 返回列表、等级·工具·物种、版本口径、盲区原文、每个工具的「何时用」「必填」、试调页跳转按钮。
- §3 的两态：状态行「构建期清单 · N 源 / M 工具」（口径写在 title）、空态「清单未注入」且**不给任何计数**。
- 图标唯一来源 `src/core/source-icons.json`，构建复制到 `dist/core/`；缺图标的源会让 `npm run build` 失败，面板同时用「?」占位。
- 跳转按钮未配置地址时 `disabled` 并写明原因（不渲染看起来能点的按钮）。
- 证据：`test/client.test.ts` 21 例、`npm run build`、`check:counts`（含置顶顺序与源图标断言）。

**未实现（v2，受环境限制，不是漏做）**

- `/healthz`、`tools/list` 实时数据、子集核对黄条、401 / 403 / 离线三态：**客户端 ↔ 宿主这条通道目前不存在**——`src/client/` 拿不到 token 校验结果、服务地址与实时工具表，硬做只能靠猜。
- 因此 §3 的「载入态超过 8 秒」也只对 v2 有意义：v1 的快照是同步注入的，没有等待过程。
- 补法：先在宿主侧暴露 healthz / tools.list 的路由，再按 §5 的三步接线（发头 → 回读 → 比对 → 不符就报黄条）。

> 验收时请按这两栏分开判：v1 的项可以用离线测试与构建证据判；v2 的项要等宿主路由到位，别拿稿要求实现方现在补。
