## 1. 这是什么、边界在哪

浏览器打开就能：**看这个服务提供哪些源与工具**、**对任意一个工具发起一次真实调用**、**看到带出处的原始结果**。
它是同一份注册表的第三个出口（前两个是 stdio MCP 与 DSH 插件），不是另一个数据库门户。

**做**：浏览、搜索、试调、看结果与出处。
**不做**：账号体系、保存调用历史到服务端、批量下载数据、图表分析。判据仍是仓规那句——「怎么把数据问出来」归这里，「问出来之后怎么用」不归。

## 2. 事实基础（都是本机实测，不是推测）

设计只依赖这些已经验证过的服务端行为：

| 事实 | 实测 |
|---|---|
| `/mcp` 是 **stateless** streamable HTTP：每个 POST 独立，不返回 `mcp-session-id` | `initialize` → 200，响应头无 session id |
| **不需要先 initialize** 就能 `tools/list` | 单独一个 POST `tools/list` → 200，直接返回工具数组 |
| `tools/call` 正常 | `hub_status` → 200，`result.content[0].text` 是排版好的文本 |
| 没有 token 时 | `401 {"error":"unauthorized"}` |
| Origin 不在白名单时 | `403 {"error":"forbidden origin"}` |
| 服务端**不下发 CORS 响应头** | `access-control-allow-origin` 为空 → **跨源浏览器调用不可能成功** |

**由此定一条硬架构**：试调页必须与 `/mcp` **同源**部署（Nginx 同一域名下静态站 + `/mcp` 反代），
不做「前端在 A 站、服务在 B 站」的跨源方案——那需要服务端加 CORS，属于改服务端契约，不在这一版范围。
部署侧必须把页面域名写进 `PLANTOMICS_HUB_ALLOWED_HOSTS`，否则浏览器带着 Origin 打过去就是 403。

## 3. 信息架构

```
顶栏（全局）
├── 品牌 + 当前服务地址 + 连接状态灯（/healthz 结果）
└── 访问 token 输入（password，只放 sessionStorage）

① 浏览源        #/sources                ← 默认页
   ├── 源列表（8 个，按名称/等级/工具数）
   ├── 关键词过滤（源名、物种、工具名）
   └── 每个源：等级徽章 · 工具数 · 覆盖物种 · 盲区条数

② 工具详情      #/tools/<toolName>
   ├── 工具名 + 所属源 + 等级
   ├── 描述（什么时候该用它，原文来自注册表）
   ├── 参数表（由 inputSchema 生成：名字 / 类型 / 是否必填 / 说明）
   └── 「去试调」按钮 → ③（把工具名带过去）

③ 试调          #/try/<toolName>
   ├── 左：参数表单（随 inputSchema 变）
   ├── 中：请求预览（可复制的 JSON-RPC 片段 + curl 片段）
   └── 右/下：结果面板
        ├── 状态：未连接 / 401 / 403 / 网络失败 / 调用中 / 成功 / 工具报错
        ├── 正文：result.content[].text（原样，不重排）
        └── 出处尾注单独高亮（源 / 完整请求 / 状态 / 耗时 / 查询时刻）
```

URL 用 hash 路由（`#/…`），好处：纯静态、Nginx 不需要 rewrite、`file://` 直开也能走。

## 4. 认证：token 绝不进代码

三条路径，按优先级：

| 方案 | 做法 | 代价 | 取舍 |
|---|---|---|---|
| **A（默认）用户自带 token** | 顶栏 password 输入 → 存 `sessionStorage` → 每次 fetch 带 `Authorization: Bearer …` | 每次新开标签页要重新粘一次 | **选它**：token 不进代码、不进构建产物、不进 localStorage、不上报 |
| B（可选）同源代理注入 | Nginx/小服务在 `/mcp` 前缀补 token，浏览器不带 token | 代理里得有 token（读环境变量文件，权限 600） | 部署时若不想让访客要 token，再用它；本版不做 |
| C 无 token 只读 | — | 服务端未配 token 时本来就不鉴权（仅回环） | 公网部署必须配 token，否则谁都能调；页面不为它设计 |

**红线（实现时逐条对）**：

- token 只存在于内存与 `sessionStorage`；**不写 localStorage、不写 cookie、不进 URL、不进日志**。
- 构建产物里 grep 不到 token 字样；示例代码里只有 `<token>` 占位。
- 401 时**清空**输入框旁边的状态并提示重填，不回显 token 前后缀。
- 「复制请求」按钮复制的是 `Authorization: Bearer <token>` 占位版，不是真 token。

**每个面板都必须有这些状态**（线框里逐页可切）：

| 状态 | 触发 | 呈现 |
|---|---|---|
| 无 token | 首访 | 结果区提示「先填 token」，输入框高亮，不发请求 |
| 401 | token 错 | 「token 被拒（401）」+ 清状态，不回显 token |
| 403 | 域名没进白名单 | 「服务端拒绝来源（403）—— 部署侧需把本站域名加入 `PLANTOMICS_HUB_ALLOWED_HOSTS`」 |
| 网络失败 | 服务没起 / 断网 | 「连不上服务」+ 实际尝试的地址 + 重试按钮 |
| 调用中 | — | 按钮禁用 + 计时；超过 20 s 显示「仍在等待」 |
| 工具报错 | `result.isError` | 原样显示服务端给的错误文本，不翻译不改写 |
| 成功 | — | 正文 + 出处尾注高亮 + 耗时 |

## 6. 数据从哪来（浏览页与试调页不是同一个真相）

- **浏览页**：读 `site/data/catalog.js`（构建期快照，由 `build-data.mjs` 从 `dist/` 生成），离线、可 `file://` 直开，但**必须标快照时间与 commit**，并说明「不表示上游可用」。
- **试调页**：一律以**服务端实时返回**为准（`tools/list` 拿工具与 `inputSchema`，`hub_status` 报服务端自己的规模）。
  两边数字不一致时**以服务端为准并显式提示**——这正是「已发布包 7/34 与源码 8/37 不同」那类问题的现场版。

## 7. 响应式与可读性

- ≥1024px：三栏（源列表 / 详情 / 结果）；768–1023：两栏（列表 + 内容）；<768：单栏，列表变成顶部横向 chips。
- 结果里的长文本（含出处）用等宽字体 + `overflow-wrap: anywhere`，不允许横向溢出；窄屏下结果面板整宽。
- 中文行高 ≥1.7，正文 15–16px；主色只用于可点元素与状态灯，正文对比度按 WCAG AA 检查。
- 键盘可达：Tab 顺序 = 顶栏 → 列表 → 详情 → 试调；输入框有 label；状态变化用 `aria-live="polite"` 播报。

## 8. 实现范围建议（请拍板）

第一版做全三页，但**参数表单只支持 `string` / `number` / `boolean` 三种标量**，数组与对象先用「原始 JSON 文本框」兜底；
不做历史记录、不做收藏、不做多服务切换。这样能在一屏内验完「能浏览、能调用、有出处」三件事。
