# 市场首屏设计稿（FE-01）

> 状态：**设计稿 + 可点开线框**。实现与 `/catalog` 接线归后续；本稿只定信息层级、数字来源、阈值行为与三态。
> 线框：`web/market-sketch.html`（数据走 `GET /catalog`，接口未上线时全页显示「待 /catalog」）。

---

## 1. 它是什么

首页最醒目的位置是**源市场**：用户在这里看到有哪些源、每个源能查什么、盲区在哪，勾选自己需要的源，实时看到**订阅集**的成本。

一句话口径：**库房不设上限，书包设上限**——全库源与工具不拦截，唯一硬阈值是单次订阅集 ≤ 80 工具。

## 2. 数据来源（唯一真相是 `GET /catalog`）

- **实时**：`GET /catalog`，只读、免鉴权，由**运行中的注册表**实时生成。
- **接口未上线时**：所有数字位显示「—」并挂「待 /catalog」黄标，卡片只画字段骨架。
- **禁止**：拿 `site/data/catalog.json` 这类**构建期快照**冒充活数据。快照回答的是「构建那一刻源码有什么」，不是「这个服务现在能给你什么」——两者不同，混用就是公开页面上的错。

期望字段（与后端确认后固定；缺字段不猜，按「待 /catalog」处理）：

```json
{
  "generatedAt": "ISO-8601",
  "metaTools": ["hub_find_sources", "hub_status"],
  "sources": [
    { "id": "strawberry", "name": "…", "nameEn": "…", "tier": "T1",
      "toolCount": 5, "species": ["Fragaria vesca"], "blindSpots": ["…"] }
  ]
}
```

## 3. 数字来源标注（每个数字位都要有）

| 标签 | 含义 | 用在哪 |
|---|---|---|
| 绿标 `/catalog` | 直接来自接口字段 | 源数、每源工具数、盲区条数、数据时刻 |
| 灰标 `推算 · 工具数 × 280` | 由接口数字推算，公式写在标签里 | 预估 token |
| 黄标 `待 /catalog` | 接口未就绪，此位为空 | 上表所有位在接口缺失时 |

阈值本身（40 / 80）标「仓规 v2.3」，因为它们是**规则常量**不是取数结果——但页面不许把它们当数据展示成「当前值」。

## 4. 源卡片

一源一卡，固定字段：

- 图标（`assets/source-icons.js`，与落地页同一枚）
- 源名（中文优先）+ 英文名
- 等级徽章（T1/T2）
- **工具数**（带来源标）
- 覆盖范围（`species` 原文）
- 盲区：默认折叠，展开是 `blindSpots` **原文**，不翻译、不改写
- 勾选框（订阅/取消订阅）

> 覆盖范围目前直接显示拉丁名。要做「小麦 / 水稻 / 草莓」这类作物名，需要一份**作物别名表**；它和置顶、图标一样必须是单一来源，不许在本页再手写一份。这条列进待办，不在本稿范围。

## 5. 订阅集计数条（常驻、粘顶）

四个数字 + 一条预算条：

| 位 | 内容 | 来源 |
|---|---|---|
| 已订源 | 选中源个数 | /catalog |
| 工具数 | Σ(选中源 toolCount) + 元工具数 | /catalog |
| 预估 token | 工具数 × 280 | 推算（标签写公式） |
| 警示线 / 硬上限 | 40 / 80 | 仓规 v2.3 |

**阈值行为**（与 `AGENTS.md` §10.2 对齐）：

- `≤ 40`：正常，无提示。
- `> 40`（警示，仍可用）：黄色说明——多少 token、32K 上下文占比、「工具越多选错源概率上升（未实测，已知风险）」。
- `> 80`（拒绝）：红色，标题写「**超过硬上限 80，这一组不能用**」，并给**可操作**的两条：砍掉哪些源（至少再减 N 个工具）、或拆成两次会话各订一部分。拒绝态下「开始使用」按钮禁用。

预算条按 80 归一（不是 40）——硬上限才是分母，40 只是黄线。

## 6. 数据时刻

页面右上常驻「**数据时刻：2026-11-01 03:24Z（来自 /catalog）**」，取 `generatedAt`；缺失则退回响应时间并注明「响应时间，非数据生成时间」。

**不许**只写「实时」两个字——「实时」是承诺，「时刻」是证据。

## 7. 三态

| 态 | 触发 | 呈现 |
|---|---|---|
| 载入 | 首屏请求中 | 骨架卡 3 张 + 计数条全部「—」，**不显示任何数字** |
| 就绪 | `/catalog` 200 | 正常渲染 |
| 未就绪 | 404 / 网络失败 / 非 JSON | 顶部黄标「数据时刻：待 /catalog」+ 说明（含实际错误）+ 骨架卡；计数条保持「—」；**不降级到快照** |

「就绪但 0 个源」单独处理：显示「/catalog 返回 0 个源——这不是正常状态」，不渲染成「没有数据源」的空市场。

## 8. 与 `web/` 其它页的复用边界

| 东西 | 复用 | 说明 |
|---|---|---|
| `style.css` 变量与基础组件 | ✅ | 同一套配色、暗色跟随 |
| `assets/source-icons.js` | ✅ | 同一源必须同一符号 |
| 试调页与 MCP 调用 | ❌ | 市场只负责「选装」，不发起调用 |
| token 输入 | ❌ | 本页**没有**任何凭据输入；`/catalog` 免鉴权 |
| `data/catalog.js` 构建期快照 | ❌ | 见 §2 禁止项 |

## 9. 不做的事

- 不显示上游探活/延迟（那是 `/healthz` 与 probe 的事，放这里会被读成实时监控）。
- 不做「推荐组合」自动勾选——默认**一个都不选**，订阅是用户的决定。
- 不在页面里出现任何 token、密钥、内部主机名或个人路径。

## 10. 验收清单（对应审查五条）

1. 能打开、可交互：勾选/取消即时改变订阅集数字与预算条。
2. 窄屏（390/320）无横向溢出，卡片单列可读。
3. 暗色正常：卡片、标签、黄/红提示都在暗色下可读。
4. **每个数字位都对得上来源**：绿标位能在 `/catalog` 响应里找到同值；灰标位符合 `工具数 × 280`；接口缺失时全是「—」+「待 /catalog」。
5. **无凭据泄漏**：全页无 token 输入、无 `Authorization`、无内部主机/路径。
