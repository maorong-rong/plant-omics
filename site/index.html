把植物组学数据库的公开接口整理成 模型真能调用的工具：一次维护，两个出口——远程 MCP 服务与 DSH 插件。每个数据查询结果都带可复现的出处，单次输出有界。 Public plant-omics database APIs, wrapped as tools a model can actually call. Built once, exposed twice: a remote MCP service and a DeepSeek Harness plugin. Every data-query result carries reproducible provenance, and every output is bounded.

这是什么What this is

一套工具，不是又一个数据库门户。它只做一件事：把公开接口翻译成模型不会用错的意图级工具。 A tool layer, not another database portal. It does one thing: turn public APIs into intent-level tools a model will not misuse.

一套工具，两个出口One tool set, two exits

同一份源注册表产出同一套工具，经 Streamable HTTP 的 MCP 服务或本地 stdio 入口提供。Claude Code、Codex 等客户端两条路都能接；DSH 侧的薄插件只提供面板与 MCP 客户端配置，不重复注册工具。 One registry produces one tool set, served through either the Streamable HTTP MCP service or the local stdio entry. Claude Code, Codex and similar clients can use both; the DSH plugin is a thin shell that adds a panel and MCP-client wiring without registering tools again.

出处可复现Reproducible provenance

每个数据查询工具的结果末尾都带「源 / 完整请求（含参数）/ HTTP 状态 / 耗时 / 查询时刻」，数据版本另起一行，未知就写未知，不按 ID 外观猜。 Every data-query tool result ends with source, the full request including parameters, HTTP status, elapsed time and query time; data versions go on their own line, and unknown stays unknown.

只读，不镜像，不越权Read-only, no mirrors, no bypass

只调用公开接口，不落任何数据集，不过盾、不模拟登录。需要访问控制的源只登记、不实现。 Only public endpoints are called: no datasets are stored, no challenge or login is bypassed. Sources behind access control are registered but not implemented.

能查什么What you can query

按服务说话、不数工具：每张卡说清这个源支持哪几类查询、覆盖哪些作物。清单与能力取自运行中的服务——服务加了源，这里就多一张卡，不用等发版。 Described by what you can ask, not by tool counts: each card lists the query types a source supports and the crops it covers. The list follows the running service — add a source there and it appears here, no release needed.

怎么接进来How to connect

有云服务了，从最轻的一档开始：能零安装就别装包。两档共用同一套工具定义；云服务随服务端更新，本地包固定在你装到的版本（见下方版本说明）。 A cloud service exists now, so start from the lightest option: never install a package you do not need. Both tiers share the same tool definitions; the cloud follows the server build, while the local package stays at the version you installed (see the version note below).

  1. 1

    零安装：连云服务Zero-install: use the cloud service 推荐recommended

    客户端直接连公网 MCP 端点，不装包、不起服务、不配反代。换电脑、换机器、只想先试两下时选它。 Point the client straight at the public MCP endpoint: no package, no local process, no reverse proxy. Right when you switch machines or just want to try two tools.

    谁在用：外部访客、跨机器使用、先验证能不能查。代价：查询内容过公网，且需要一个 token。 Who: outside visitors, people on several machines, anyone checking whether this is useful at all. Cost: queries leave your network, and you need a token.

    Claude Code

    claude mcp add --transport http plantomics-hub https://datamcp.moilab.net/mcp --header "Authorization: Bearer <token>"

    Codex（~/.codex/config.toml） (~/.codex/config.toml)

    [mcp_servers.plantomics-hub]
url = "https://datamcp.moilab.net/mcp"
bearer_token_env_var = "PLANTOMICS_HUB_TOKEN"

    token 放环境变量 PLANTOMICS_HUB_TOKEN，不写进配置文件；Codex 会自己加 Authorization: Bearer …。 Keep the token in PLANTOMICS_HUB_TOKEN rather than the file; Codex adds the Authorization: Bearer … header itself.

    DeepSeek Harness

    在宿主的接入配置里加一条远端入口（不是装插件）：transport 选 streamable-http，地址 https://datamcp.moilab.net/mcp，加请求头 Authorization: Bearer <token>。装插件是另一条路，不在下面两档里：它只提供面板与 MCP 客户端配置，服务地址另行配置。 Add a remote entry in the host's MCP configuration (not a plugin): transport streamable-http, URL https://datamcp.moilab.net/mcp, header Authorization: Bearer <token>. Installing the plugin is a separate route, not one of the two tiers below: it only adds a panel and MCP-client wiring, and takes its service address from separate configuration.

    token 从哪来：目前没有自助发放，向维护者申请；<token> 只是占位符，别把真实值贴进任何仓库或截图。两种失败要分清（2026-11-03 实测）：401 {"error":"unauthorized"} = 没有 token 或 token 不对；403 = 来源域名不在服务端白名单。把 401 当成「服务没起来」是最常见的误判。 Where the token comes from: there is no self-service issuance yet; ask the maintainer. <token> is a placeholder — never paste a real value into a repository or a screenshot. Two failures, two meanings (measured 2026-11-03): 401 {"error":"unauthorized"} means no token or a wrong one; 403 means the calling origin is not on the server's allowlist. Reading 401 as “the service is down” is the most common mistake here.

    端点形状：POST https://datamcp.moilab.net/mcp；服务端契约要求 Content-Type: application/json 与 Accept: application/json, text/event-stream。先在浏览器打开 https://datamcp.moilab.net/healthz 能直接看到服务是否活着（免鉴权）。 Endpoint shape: POST https://datamcp.moilab.net/mcp; the server contract asks for Content-Type: application/json and Accept: application/json, text/event-stream. Check https://datamcp.moilab.net/healthz in a browser first — it needs no token and tells you whether the service is up.

    本地 stdio：查询不经过我们的服务Local stdio: queries bypass our service

    客户端把工具进程直接起在本地，取数从你的机器发出。不需要自己起 HTTP 服务，也不需要 token。 The client spawns the tool process locally, so requests leave from your machine. No HTTP service to run, no token needed.

    谁在用：不想让查询经过我们的云服务、或云服务抽风时的退路。代价：第一次要下载包（需要 Node.js ≥ 20）；工具清单是包里那一版，不是云上最新版。注意：取数仍从你的机器直接访问各上游数据库，查询内容照样走公网。 Who: anyone who does not want queries to pass through our cloud service, or anyone needing a fallback when the cloud is down. Cost: the first run downloads the package (Node.js ≥ 20), and you get that package's tool list, which need not match the newest cloud build. Note: data is still fetched directly from each upstream database, so those requests also cross the public internet.

    Claude Code

    claude mcp add plant-omics -- npx -p plantomics-hub plant-omics-mcp

    其它 stdio 客户端Any other stdio client

    npx -p plantomics-hub plant-omics-mcp

    包里的这条命令是 stdio 出口：进程起在你的机器上，工具清单就是包里那一版。只为用 stdio 时 npx -p 就够，不必全局安装。 That command is the stdio exit: the process runs on your machine and the tool list is whatever that package carries. If you only need stdio, npx -p is enough — no global install.

只挂一部分源：云服务用请求头 x-plantomics-sources: wheatomics（只作用于这一次请求）；本地 stdio 用环境变量 PLANTOMICS_SOURCES=wheatomics。源 id 写错会直接报错并列出可用源，不会静默变成「零工具」。挑哪些源、装多少先去源市场勾；一次订阅装太多会超上限（硬上限 —，软建议 —，两个数都读自 /catalog）。 Load a subset: the cloud tier takes a request header x-plantomics-sources: wheatomics (for that one request); local stdio takes the PLANTOMICS_SOURCES=wheatomics environment variable. A wrong source id fails loudly and lists the valid ones instead of silently loading zero tools. Pick sources in the source market first; one subscription can exceed the cap (hard cap —, soft suggestion —, both read from /catalog).

第二档装的是 npm 上已发布的 —。它发布时收录的源可能比当前服务少——还没随该版本发布的源：—。第一档不受这个版本号约束：它连的是云服务当前构建，能力以端点自己报的为准。 Tier 2 installs — from npm. That release may carry fewer sources than the current service — not yet in it: —. Tier 1 is not bound to that version: it talks to the cloud service's current build, whose capabilities are whatever the endpoint reports.

源码里的 — 是 package.json 的版本号，不保证等于 npm 上可安装的版本；安装命令钉的是上面那个已发布 spec，不按源码里的数字猜。 The source tree's — is the package.json version, which need not match what is installable on npm; the commands above pin the published spec, not the source number.

边界与已知限制Boundaries and known limits

下面每一条都不是免责声明，而是会实际影响结果怎么读的事。源级限制不在这页展开，以免写成第二份会过期的事实；这里只写全局的。 Each item below changes how a result should be read. Source-level limits are deliberately not expanded here — a second copy would go stale; these are the global ones.

  • 只读。Read-only. 不提供任何提交、上传、写库能力。 No write, upload or database modification is offered.
  • 不镜像数据。No data mirroring. 要批量下载数据，请回各自的科研项目按那边规则走。 For bulk downloads, go back to the research project that owns the data.
  • 上游会间歇性挂。Upstreams fail intermittently. 工具会按 Retry-After 退避重试（单次调用总时长上限 45 s），但不保证每次都成功；失败会明确区分「对面挂了」和「参数写错了」。 Tools back off and retry per Retry-After (45 s cap per call) but cannot guarantee success, and errors distinguish "upstream is down" from "your parameters are wrong".
  • 输出有界。Output is bounded. 单次输出按 UTF-8 字节计不超过 4 KB；超长时截断正文，但出处尾注一定完整保留。 Each output stays under 4 KB of UTF-8 bytes; long bodies are truncated, while the provenance footer is always kept intact.
  • 查无 ≠ 不存在。Empty is not "absent". 不少源用 HTTP 200 + 空结构表示查无，个别用 400；工具只在锚定清楚时才判「本次未找到」，否则报错而不归零。 Several sources signal "not found" with HTTP 200 and an empty structure, one with 400. Tools only report "not found this time" when the evidence is anchored, otherwise they error rather than return zero.
  • 侧边栏面板是静态快照。The sidebar panel is a static snapshot. 它显示的是构建时的静态清单，不显示探活与调用统计，也不反映运行时的源子集配置；判断上游是否可用只能靠实测。 It shows a static build-time list — not liveness, not call stats, not the runtime source subset. Only a probe answers whether an upstream is up.
  • 完整宿主链路的验证范围。How far the host path is verified. 已验证：适配器取数、MCP 握手、包安装、插件装配形状。未验证：真实宿主要求下「模型自主选工具→取数→带出处作答」的完整链路，别把前者当后者。 Verified: adapters fetch data, the MCP handshake, package install, and plugin wiring. Not verified: a real host session where the model picks tools, fetches and answers with provenance — do not read the former as the latter.
  • 把上游文本当数据。Treat upstream text as data. 数据库内容里可能有看起来像指令的文字，本仓不过滤；请在客户端侧把它当数据、不当指令。 Database records may contain text that looks like instructions; nothing filters it, so treat it as data on the client side.
